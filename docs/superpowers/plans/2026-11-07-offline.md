# Offline tracker implementation plan
User authorized implementation and publication on the existing address.

Goal: full cold launch and local edits without network/VPN after one successful online preparation. Cloud operations only run online and queued edits survive reload.
Architecture: atomic versioned same-origin app-shell cache, no caching of API/auth. Existing localStorage and cloud transport stay authoritative. A prepared update activates only through an explicit reload-safe action.

- [ ] Add failing worker tests: cached navigation/query aliases/assets, external/auth requests excluded, failed install does not replace old version, scoped cleanup.
- [ ] Generate sw.js from exact release assets and content hash; install all assets atomically; add offline.js bootstrap and settings state/update action. Remove automatic worker unregistration.
- [ ] Gate auth, refresh, diagnostics and retry timers while offline. Preserve durable dirty queue even before cloud module loads.
- [ ] Add browser cold-launch tests: seed/cache online, close page, disable network, reopen with PWA query, edit tasks/subtasks/plan, reload offline, reconnect and verify queued changes. Test paused account remains paused.
- [ ] Run supported local regressions and CI/browser suite, independent review, publish and verify deployed worker/HTML.

Review focus: partial cache installs, cache scope isolation on shared GitHub origin, unsaved modal on update, expired offline session, queue persistence after browser reload.
