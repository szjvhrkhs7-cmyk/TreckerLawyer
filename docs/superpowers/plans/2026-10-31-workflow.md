# Lawyer workflow implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Four useful sections, persistent priority board, less decorative UI and reliable local editing.
**Architecture:** Pure workflow-model.js exposes scope-safe ordering and bounded draft history; existing UI modules consume it. Existing storage keys and sync hooks remain authoritative.
**Tech Stack:** Static HTML, CSS, browser JavaScript, Node assert/vm tests.
**Spec:** docs/superpowers/specs/2026-10-31-workflow-design.md

## Global Constraints
- Preserve user data, authentication, GitHub Pages address and dark capsule style.
- Four sections: Сегодня, Задачи, Приоритеты, Дела.
- Scheduling never changes a task deadline.
- No pretend cloud or attachment synchronization.

## Review Focus
- Root/project tasks with equal ids remain distinct during moves.
- Storage failure must not silently commit a partial reorder.
- Drag cancel, mobile scroll and keyboard focus must remain usable.
- Draft recovery must preserve the current revision and sanitize stored HTML.
- Sync status must not claim an uploaded copy after only a local save.
